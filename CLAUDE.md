## Uruchamianie

```powershell
pip install -r requirements.txt
Copy-Item .env.example .env             # klucz API — patrz niżej
python -m app.main                      # GUI (PyQt6)
```

**Świeży klon**: aplikacja startuje BEZ `.env` (klucz sprawdzany dopiero przy wywołaniu — `gemini_client` rzuca „Brak GEMINI_API_KEY"), `Style/tla_przodu/` z presetami JEST w repo, pozostałe kategorie (`postac`, `rewers`, `wartosci`, `pudelko`) tworzy `style_store._ensure()` jako pusty preset `Domyślny` (puste pole = wartość domyślna z `_CATEGORY_FIELDS`, więc prompty działają od razu). Czego NIE ma i co z tego wynika: brak `rewers.png` (eksport dwustronny/atlas/KRM niepełne), pusty `Style/Pudełka/` (widok Pudełko zgłasza błąd, wykrojnik = PDF od drukarni + sidecar `<nazwa>.json` z mm), brak zdjęć, brak profilu `.icc` (CMYK bez zarządzania kolorem). Opis funkcji od strony użytkownika (widoki, znaczenie opcji, warianty eksportu) jest w `README.md` — przy zmianach w GUI aktualizuj oba pliki.

Zmienne środowiskowe (`app/config.py`, `.env` czytany tylko z korzenia repo): `GEMINI_API_KEY` (AI Studio), `GOOGLE_GENAI_USE_VERTEXAI` + `GOOGLE_CLOUD_PROJECT` + `GOOGLE_CLOUD_LOCATION` (Vertex przez ADC, domyślnie `us-central1`), `CUSTOM_API_KEY` (slot, nieużywany przez generację), `KARTY_FAKE_API=1` (atrapy), `TEST_OUT` (katalog wyników skryptów `test_*`).

Zależności opcjonalne (importy leniwe — brak degraduje tylko część funkcji): `reportlab` → wszystkie PDF-y (A4, KRM, JKB, pudełko), `PyMuPDF` (`fitz`) → wektorowe wykrojniki PDF i eksport „na wykrojnik drukarni", `pypdf` → wymagany przez `scripts/test_eksport.py`, ale **nie ma go w `requirements.txt`** (`pip install pypdf`).

## Architektura

Przepływ generacji: **widoki GUI → sygnały → `main_window` → QThread w `app/gui/worker.py` → `app/core/generator.py` → `app/api/gemini_client.py`**. Widoki nie wołają API bezpośrednio; `main_window._wire_views()` jest centralnym punktem łączenia sygnałów.

### Konfiguracja (`app/config.py`)
Centralny, **mutowalny** moduł: ścieżki, rejestr modeli, format karty. GUI mutuje w runtime m.in. `SELECTED_MODEL`, `USE_VERTEX`, `TEMPLATE_OVERRIDES` (wybór wariantu tła per kolor). Rejestr modeli `MODELS` to **stała, ręcznie kuratorowana lista** — dynamiczne odkrywanie przez API zostało wycofane (wpuszczało modele wizyjne niegenerujące obrazów).

### Presety stylu (`app/core/style_store.py`) — jedno źródło prawdy
Cały wygląd talii żyje w folderach `Style/<kategoria>/<preset>/` (kategorie: `postac`, `tla_przodu`, `rewers`, `wartosci` — typografia narożników: czcionka .ttf w folderze presetu, rozmiary/offsety/obwódka/cień w % wysokości tarczy, kolory hex; parsowanie w `compositor.styl_z_presetu()`; kolory czerwony/czarny zasilają też paletę promptów AI przez `prompts.style_lock()`; aktywne wybory w `Style/active.json`). Dawna kategoria `styl_tla` jest SCALONA z `tla_przodu` jako pole `styl` (wspólny opis ornamentyki, `template_style()`; jednorazowa migracja `_migrate_styl_tla()` w `load()`, stary folder `Style/styl_tla/` jest ignorowany — nie przywracać kategorii). Preset `postac` ma też `poziom_kreskowki` (1-5, domyślnie 5 = pełny cell-shading): suwak „Poziom kreskówki" na Ekranie roboczym (w miejscu usuniętej sekcji „TŁO KART (WYBÓR)" — wybór wariantu pliku tła i klasa `TemplatePicker` USUNIĘTE; aktywne tło ustawia preset + `config.TEMPLATE_OVERRIDES` po generacji/imporcie), w promptach `prompts.cartoon_level_clause()` (poziom 5 = pusty string, status quo; `style_lock()` łagodzi wymóg cell-shadingu przy poziomie < 5; twarze zawsze pod `face_fidelity_clause`). **Obrazy istnieją tylko tam — bez kopii roboczych**: silnik/eksport/GUI czytają przez `Suit.available_templates()` (skan `style_store.front_dir()`) i `style_store.back_path()`; generator zapisuje nowe tła/rewers (i backupy `rewers_stary_*.png`) wprost do folderu aktywnego presetu. Puste pole tekstowe presetu = wartość domyślna z `_CATEGORY_FIELDS`. Presety `tla_przodu` i `rewers` mają pole `tryb_wlasny` („1" = prompt presetu idzie do modelu DOSŁOWNIE, bez wbudowanych dopisków layoutu — np. karty do planszówek; akcesory `front_custom_mode()`/`back_custom_mode()`, dopiski w `prompts.front_layout_suffix()`). `load()` przy starcie robi jednorazowe migracje (stary `styles.json`, legacy `tla_kart/`). Zmiana presetu `tla_przodu` musi czyścić `config.TEMPLATE_OVERRIDES` (wskazują pliki poprzedniego presetu).

### Klient API (`app/api/gemini_client.py`)
Jedno wejście do generacji obrazu: `generate_image(contents, seed=…, temperature=…, aspect_ratio=…, retries=…)` (generate_content, tekst+obrazy PIL) — pozostałe funkcje (`edit_card_image`, `compose_full_card`, `edit_region`, `stylize_photo`) to cienkie nakładki, a `generate_text()` obsługuje wywołania tekstowo-wizyjne (analiza zdjęć). `aspect_ratio` idzie do `image_config` — **model honoruje proporcję TYLKO tędy**, nie z treści promptu (stąd `pudelko.najblizszy_aspect()`). Dwa źródła wg `config.USE_VERTEX`: klucz AI Studio albo Vertex AI przez ADC; klienci cache'owani per region — rodzina `gemini-3*` wymaga endpointu `"global"` (`config.vertex_location_for`). Błędy mapowane na `FatalAPIError` (przerywa serię) vs retry z WYKŁADNICZYM backoffem + jitter (`_odczekaj`, ~1/2/4/8 s do `_BACKOFF_MAX_S`) — jeden zryw sieci nie może wywrócić wielowywołaniowej generacji (pudełko potrafi zrobić kilkanaście wywołań pod rząd); pusta odpowiedź podbija temperaturę o `PUSTA_TEMP_BUMP`. **Modele Imagen zostały wyłączone przez Google (VI 2026) — nie hardcoduj ich**; nowy model = ręczny wpis w `config.MODELS` + opis w `MODEL_DESCRIPTIONS` (`settings_view.py`).

### Rdzeń (`app/core/`)
- `generator.py` — orkiestracja trybów: HYBRID (kolaż + `edit_card_image`) i FULL_AI (`compose_full_card`); tła (`generate_template` — tryb kompletu 4 kolorów: `reference`/`use_auto_reference`/`seed`, sekwencję prowadzi `TemplateSetWorker`), rewers (`generate_back`) i własne tło użytkownika (`import_template`, bez API; parametr `rozciagnij` — całość obrazu ściśnięta do dokładnej proporcji formatu zamiast docięcia środka, przy odchyle proporcji > 8% GUI pyta użytkownika, poniżej rozciąga bez pytania); honoruje `KARTY_FAKE_API`. **Normalizacja teł** (`normalizuj_szablon`, offline, idempotentna): każdy plik tła jest ROZCIĄGANY (cały obraz, bez docinania) do `config.template_target_size()` — DOKŁADNEJ proporcji pikseli formatu (`config.CARD_RATIO` z calowego pierwowzoru: poker 5:7 → 1695×2373, bridge 9:14, tarot 7:12, mini 7:10) w skali najbliższej `config.TEMPLATE_STD_SZEROKOSC` (=1696 px — skala strojenia stałych `KLAMP_*`); wywołania: import/generacja tła, start `_build_card_raw` i wybór tła w GUI (łapie pliki wrzucone ręcznie do folderu presetu i zmianę formatu w Ustawieniach); oryginał ląduje jednorazowo w podfolderze `zrodla/` (niewidocznym dla `available_templates`) i kolejne normalizacje liczą się od niego, a sygnatury wyników w `zrodla/_znormalizowane.json` wykrywają PODMIANĘ pliku pod tą samą nazwą (nowa treść staje się oryginałem zamiast zostać wskrzeszona ze starego zrodła); `normalizuj_szablon(wymus=True)` pomija guard idempotencji i przelicza od oryginału, a `renormalizuj_wszystkie()` robi to dla całego aktywnego presetu (przycisk „Dopasuj istniejące tła do formatu" w zakładce Tła i rewersy — tła docięte starym zachowaniem odzyskują pełną treść); przy imporcie własnego tła z odchyłem proporcji > 8% GUI pyta: rozciągnąć czy dotnąć; nadpisanie podbija mtime → cache masek/kolażu unieważniają się same. Pipeline kart: surowe wyjście AI (bez narożników) → `output/_raw/*.png` (bezstratne), finalna karta = raw + stempel narożników → `output/*.jpg`; `przestempluj_plik()` odtwarza finalne z raw bez API; wyjście modelu SPRZED klampu ląduje w `output/_raw/api/*.png` — `python -m scripts.test_klamp` przelicza na nim maskę klampu offline (podglądy: sylwetka/final/co-cofnięte) do strojenia stałych `KLAMP_*` bez API. **OBA tryby przechodzą przez `_klamp_do_szablonu()`** — klamp ADAPTACYJNY (`masks.maska_klampu`): rdzeń bezwarunkowy = OKNO symbolu (maska centrum — tło modelu przycięte do konturu okna, rama/ornamenty zawsze z szablonu → identyczny symbol na każdej karcie), a BAZA kompozycji = szablon z oknem wypełnionym kolorem karty aż do konturu (`compositor.wypelnij_okno()`, maska `center_full` bez erozji — erodowany `center` zostawiał kremową szczelinę, „biały ślad" symbolu); ponad oknem przeżywa sylwetka postaci spójna z oknem, wykrywana kolorem (próg różnicy; w ringu pewności przy oknie próg obniżony na płaskim szablonie), teksturą (płaska farba na ornamencie = postać, np. skóra na kremie; anty-bleed chroni przed rozlaniem koloru okna — na kartach CZERWONYCH obejmuje też kanał kolorowy: nadmiar przerysowanego większego serca wraca do szablonu, stały rozmiar symbolu) ORAZ chromą Lab (na kremie niski próg, na ornamencie wyższy `KLAMP_PROG_CHROMA_ORNAMENT` — ratuje głowy malowane na ornamencie), z otwarciem, MOSTKIEM (`KLAMP_MOSTEK_PX` — małe domknięcie kandydatów przed filtrem spójności: niewykrywalna szyja odcinała głowę od sylwetki i filtr kasował ją w całości), filtrem min. pola, filtrem prostokątnych resztek kolażu (komponent szczelnie wypełniający bbox → szablon), LITYM domknięciem liczonym na UNII extra|core, ograniczonym do sąsiedztwa sylwetki (mostkuje pasma kremowego konturu przy granicy okna — „duch" konturu przez postacie; wnętrze sylwetki binarne, wąski feather tylko na krawędzi) i domykaniem małych dziur (linie szablonu prześwitujące przez twarz); guardrail degraduje do maski pop-out hull+ring przy hurtowym przemalowaniu; parametr `temperature` przelotowo przez `edit_region`/`generate_image`/`_generation_config`); echo modelu (odbite wejście, średni diff w regionie < `_FIX_ECHO_PROG`) wykrywa `_echo_modelu` → jedna ponowna próba z innym seedem i temperaturą +`_FIX_ECHO_TEMP_BUMP`; zdjęcie przypisane karcie (`main_window.assignments`) idzie jako OSTATNI obraz (`edit_region(photo=…)`, `prompts._FIX_PHOTO_REF` — uzupełnianie uciętych elementów sceny wiernie do oryginału), a zamiast pełnego `NO_TEXT_SUFFIX` prompt poprawki używa `prompts.FIX_NO_TEXT` (tekst SCENY, np. napis na znaku drogowym, dozwolony — pełny zakaz blokował takie naprawy; wartości/indeksy narożne wciąż zakazane i stemplowane przez compositor); technika w prompcie podąża za poziomem kreskówki (cell-shading tylko przy poziomie 5, plus `cartoon_level_clause()`), a otoczenie regionu jest twardym wzorcem stylu. **Poprawka NIE przechodzi przez `_klamp_do_szablonu`** (baza wariantu już go przeszła, a strefa allowed klampu nie zna maski poprawki i wymazywała zmiany AI poza ringiem okna — „nie widać różnicy"): w obrębie maski z szablonu wracają tylko strefy TWARDE (`masks.strefy_chronione_poprawki` — pas bordiury + tarcze narożne; frame_lines celowo nie), reszta karty poza maską zostaje bitowo nietknięta; nienaruszalność reszty karty DETERMINISTYCZNA (composite po masce użytkownika z featherem + pełny `_klamp_do_szablonu`), wynik = NOWY wariant `_vN` (`nastepny_wariant()`, oryginał zostaje w historii, akceptacja = „Ustaw jako główną"), narożniki standardowo przez `stempluj_narozniki`. Honoruje `KARTY_FAKE_API`.
- `exporter.py` — FASADA eksportu (`ExportJob` + `run_export` dla GUI/testów); realny potok w pakiecie `eksport/` (Pipeline + Strategy): `formaty.FormatKarty` z `config.CARD_PRESETS` (jedno źródło wymiarów mm; `aktywny_format()` na żywo) → Etap A `procesor.ProcesorKarty` (spad z RZECZYWISTEGO DPI obrazu + znaczniki cięcia) → Etap B `uklady.StrategiaUkladu` (`UkladPojedynczy`, `UkladAtlas` z presetami `atlas_tts`/`sprite_13x4`, `UkladA4` — siatka liczona DYNAMICZNIE z formatu, poker/bridge 3×3, tarot 2×2, mini 4×4; duplex = strony rewersów z kolumnami odbitymi lustrzanie, czyste funkcje `pozycja_komorki`/`pozycja_rewersu`) → Etap C `wyjscia.StrategiaWyjscia` (ZIP+manifest, folder PNG, PDF A4 z rasteryzowanych płócien JPEG q92, PNG); orkiestruje `manager.ExportManager`, mapowanie starych kindów w `manager_dla_joba()`. **Kind `"krm"` — druk w drukarni KRM**: Etap A `procesor.ProcesorKRM` (płótno BRUTTO = netto + spad, karta skalowana JEDNOLICIE do `format.mm_ramki` = netto − 2 × `MARGINES_BEZPIECZENSTWA_MM` i wyśrodkowana, całe tło zalane `kolor_krawedzi()` = mediana obwódki 2%, `zalej_rogi()` gasi białe zaokrąglenia narożników — prefiks jasnych pikseli per wiersz w narożnym oknie, bez cv2; brak alfy, brak znaczników cięcia) → `UkladPojedynczy(rewers_pierwszy=True)` → `WyjsciePDF_CMYK(podbicie=…)`. Konwersja w `eksport/cmyk.py`: `przygotuj_do_druku()` (pre-press 1-5: autocontrast → gamma → kontrast → saturacja → unsharp; suwak „Podbicie kolorów" w panelu Eksport + „👁 Podgląd podbicia" → `main_window._preview_print_boost`) i `_cmyk_gcr()` — pełny GCR z limitem TAC zamiast `Image.convert("CMYK")`, które dawało **K = 0** („wydruk jak przez mgłę"); z profilem w `assets/icc/` idzie ImageCms z RELATIVE_COLORIMETRIC + BLACKPOINTCOMPENSATION. To samo wyjście z CLI: `scripts/druk_krm.py`. **Kind `"jkb"` — druk w JKB Print**: nie `ExportManager`, tylko `manager.ManagerJKB` (jedyny wyjątek od zwracanego typu `manager_dla_joba()`) — DWA pliki PDF CMYK z dwóch przebiegów tego samego potoku: `<nazwa>_karty.pdf` (awersy) i `<nazwa>_rewers.pdf`, strona = netto + spad 3 mm (`ProcesorKarty(spad=True)`, full-bleed z replikacji krawędzi), znaczniki cięcia opcjonalne.
- `models.py` — `Suit` (enum z `template_path`/`available_templates`), `CardSpec`. `Suit` ma 6 elementów: 4 klasyczne kolory (`Suit.kolory()`) + 2 JOKERY (`Suit.jokery()`, `czy_joker`, nazwy `joker_czerwony`/`joker_czarny`, symbol ★, okno tła w kształcie gwiazdy — `SUIT_NAME_EN`). Jokery przechodzą przez PEŁNY pipeline (własne tło z oknem, maski flood-fillem, klamp), ale są OPCJONALNE: w talii/eksporcie/licznikach tylko gdy wygenerowane; jedyna „wartość" jokera to `JOKER` (`wartosci_dla(suit, values)` — używać zamiast surowej listy wartości przy iteracji po kartach), narożniki = pionowy napis J-O-K-E-R bez symbolu (`compositor._corner_tile_joker`), poza auto-przydziałem zdjęć (`photo_analyzer._KOLORY` zostaje czwórką), poza spritem 13×4 (w atlasie TTS pola 52-53), komplet teł generuje je za opt-in checkboxem („razem z tłami Jokerów"). Filtr siatki (`deck_grid_panel.FILTRY`) operuje GRUPAMI suitów — `current_filter()` zwraca `tuple[Suit, ...] | None`.

### Pudełko na karty (`app/core/pudelko.py` + widok „Pudełko", idx 6)
Osobny potok obok kart: grafika AI z twarzami całej ekipy nakładana na **profesjonalny wykrojnik (dieline) z drukarni**. `pudelko.py` jest w CAŁOŚCI offline (ZERO API) — wywołania modelu robi wyłącznie `generator.generate_box*`.
- **Wykrojnik = geometria, nie rekonstrukcja.** Biblioteka `Style/Pudełka/`; **oryginalne PDF-y z drukarni są źródłem prawdy** (rasteryzacja PyMuPDF @ `_PDF_RASTER_DPI`=300 do pliku-cache `<stem>.raster_300.png`, legacy PNG ukrywany, gdy istnieje PDF o tej nazwie). Legenda kolorów parsowana progami RGB: ZIELONY = spad (jego wnętrze przez flood-fill = obszar druku, bbox = kadr), NIEBIESKI = linia cięcia, CZERWONY = bigowanie. Fizyczne wymiary „design area" (mm) żyją w sidecarze `<nazwa>.json` obok wykrojnika (+ `_PRESEED_DESIGN_MM` dla dołączonych plików); brak sidecara = GUI musi dopytać. Wybrany plik = pole presetu `pudelko/wykrojnik` (`style_store.active_dieline()`), preset ma jeszcze `opis` i `tryb_wlasny`.
- **Trzy tryby kompozycji** (`SegmentedControl` w `box_view`, `_TRYBY`): `"osoby"` (DOMYŚLNY, deterministyczny — dla KAŻDEJ osoby osobne wywołanie restylingu na chroma-tle, `wytnij_osobe()` daje jedną sylwetkę, `zbuduj_scene_osob()` układa je po kolei w siatce → dokładnie N osób, bez powtórek i bez „dorysowanych" postaci), `"scena"` (jedna generacja całej sceny) i `"panele"` (przód + tył kotwiczony frontem + pełne tło = 3 generacje; boki opcjonalnie AI). Źródło osób: folder wg reguły **„1 podfolder = 1 osoba"** (`osoby_z_folderu`, fallback 1 plik = 1 osoba).
- **Wycinanie postaci jest odporne na to, co model zwróci**: `wytnij_osobe()` sprawdza, czy chroma faktycznie jest (`_CHROMA_TLO_MIN`) — jest → progowanie po `#00FF00`, nie ma (model narysował scenę) → grabCut wokół największej twarzy z kaskady Haar; zawsze zostaje NAJWIĘKSZA spójna składowa.
- **„Reżyser sceny"** (checkbox, tylko tryb `osoby`): `BoxCharactersWorker` generuje same postacie → `CharacterReviewDialog` (siatka miniatur, dopisek + „🔄 Regeneruj" przez `BoxCharacterOneWorker`, każda karta osobno) → `BoxComposeWorker` → `generator.generate_box_scena_z_osob()` (kolaż `uloz_obok_siebie` + AI komponuje przód „at a bar" i tył „around a table"). Zaakceptowane wycinki leżą w `postacie/` presetu — stąd przycisk „Wznów" (`resume_rezyser_clicked`) bez ponownej generacji.
- **Panele**: `segmentuj_panele()` dzieli obszar druku ścianami (big ∪ cięcie, dylatowane) na komponenty i nadaje role (`przod`/`tyl`/`bok`/`klapka`) po polu i proporcji; `zloz_pudelko_panele()` dosuwa maski z powrotem do linii zgięcia (`_PANEL_DOSUN_PX`), żeby łączenia nie miały szpar. Boki domyślnie = deterministyczny wachlarz PRAWDZIWYCH mini-kart talii (`wizualizacja_kart`, zero API).
- **Warianty jak przy kartach**: każda generacja/import/poprawka zapisuje parę plików do `historia/<stempel>_{raw,proof}.png` i staje się główna (wskaźnik `historia/glowna.txt`, przełączenie = kopia do ścieżek roboczych `box_glowny_raw()` / `box_glowny_proof()`). **raw = artwork BEZ linii** (baza eksportu i poprawek, w `output/_raw/`), **proof = z liniami cięcia/bigu** (podgląd). Poprawki reużywają `FixRegionDialog` → `BoxFixWorker` → `generator.popraw_pudelko()` (bez stref twardych — pudełko ich nie ma).
- **Eksport** (`generator.eksportuj_pudelko`, dokładny rozmiar fizyczny): `png` (metadane DPI), `pdf`, `cmyk` (PDF CMYK z ICC) oraz `pdf_drukarnia` — otwiera ORYGINALNY wektorowy PDF drukarni i wstawia artwork `overlay=False`, czyli POD linie wykrojnika (wymaga PDF-a jako źródła).
- Odporność: wtórne wywołania AI (tło, tył, pojedyncza osoba) idą przez `generator._box_ai_opcjonalne()` — `FatalAPIError`/anulowanie propagują, każdy inny błąd degraduje element (placeholder / jednolity krem) zamiast wywracać całe pudełko.

### Synchronizacja offline (`app/core/sync.py` + `scripts/sync_paczka.py`)
Wymiana całej pracy z drugim komputerem BEZ sieci i bez GitHuba — paczka to zwykły FOLDER przenoszony pendrivem. Cała logika offline (ZERO API), CLI i panel „🔄 SYNCHRONIZACJA (pendrive)" w Ustawieniach to dwie skorupy na tym samym module.
- **Dlaczego to nie jest zwykłe kopiowanie folderu**: `projekt.json` trzyma ścieżki ABSOLUTNE, a `_load_project` po cichu wyrzuca wpisy, których plik nie istnieje (u odbiorcy zniknęłyby WSZYSTKIE przypisania), część zdjęć leży poza ROOT, a nadpisywanie po nazwie kasuje progres drugiej osoby.
- **Tokeny ścieżek**: w paczce ścieżki żyją jako `<ROOT>/…` i `<ZEW>/…` (`token_ze_sciezki`/`sciezka_z_tokenu`); pliki spoza ROOT jadą w `dane/_zewnetrzne/<sha8>_<nazwa>` i lądują u odbiorcy trwale w `zdjecia/_zewnetrzne/`. Tokenizowane są `assignments`, `selections`, `templates`, `import_folder`, `box/osobne_folder`.
- **Import jest ADDYTYWNY — nigdy `unlink`, nigdy nadpisania innej treści.** Klasy plików (`_klasa`): `karta` (output/*.jpg + lustrzany `_raw/*.png`) → przy kolizji NOWY numer wariantu, przydzielany GRUPOWO w `_plan_kart`, żeby awers i raw dostały ten sam `_vN`; `wskaznik` (pola presetu `<pole>.txt` w korzeniu folderu presetu, `glowna.txt`, `_znormalizowane.json`) → tylko addytywne, przy różnicy TREŚĆ autora ląduje w raporcie (przemianowanie dałoby plik, którego program nie czyta); reszta → `<nazwa> (od <autor>)`.
- **`projekt.json` scalany PER KLUCZ** (`_scal_projekt`), nie podmieniany: `assignments`/`selections` per karta, przy rozbieżności domyślnie wygrywa ODBIORCA (`--przypisania=ich` odwraca), różne `values` = tylko ostrzeżenie (inne wartości = inne sloty), ustawienia UI zostają lokalne, `auto_przydzial.motywy` i `templates` uzupełniane o brakujące. Przed zapisem kopia w `kopie_zapasowe/`, przy konfliktach pełny stan autora w `projekt_od_<autor>.json`.
- **Idempotencja**: `.sync/znane.json` (sha1 → lokalna ścieżka) pomija treść, którą już mamy — także pod inną nazwą, więc kolejne wymiany nie robią lawiny „(od Marka) (od Marka)". `--od-ostatniej` czyta `.sync/wyslane_<autor>.json` i pakuje tylko nowe sha1. Fałszywe konflikty gasi `_ta_sama_tresc` (ten sam plik pod inną nazwą; w trybie `--sucho` sha1 brany z manifestu przez `zaplanowane`).
- **Profile rozmiaru** (`_dozwolony_w_profilu`): `pelny` (~9 GB), `roboczy` (bez `output/_raw/` i `historia/` pudełka — u odbiorcy nie zadziała wtedy „Przestempluj" ani selektywna poprawka przywiezionych kart), `przypisane` (jak `roboczy`, ale z `zdjecia/` i `Przypisane/` bierze WYŁĄCZNIE pliki wskazane w `projekt.json` — `_uzywane_zdjecia()`: `assignments` + zawartość `box/osobne_folder` — plus pomija `zrodla/`; zdjęcia spoza ROOT jadą jak zawsze kanałem `_zewnetrzne`, więc komplet przypisań zostaje zachowany), `lekki` (same presety tekstowe i maski).
- Nazwa paczki ma stempel z dokładnością do MINUTY — `eksportuj()` dokleja `_2`, `_3`…, gdy folder o tej nazwie już istnieje i nie jest pusty (dwa eksporty pod rząd, np. dwa profile, mieszały się w jednym folderze i rozjeżdżały manifest). Z paczki twardo wykluczone: `.env`, `assets/masks/`, `output/_raw/api/`, `Style/active.json` (podmiana aktywnych presetów byłaby nadpisaniem ustawień — jedzie tylko informacyjnie do `stan/`).
- **GUI**: `SyncWorker` (wzorzec `ExportWorker`) + `MainWindow._start_sync_export/_start_sync_import`. **Krytyczne**: na czas importu `self._sync_w_toku` robi z `_save_project()` no-op — inaczej dowolne zdarzenie UI nadpisałoby świeżo scalony plik stanem z pamięci; po sukcesie stan wraca Z DYSKU przez `_przeladuj_po_imporcie()`.

Tryb single (1 plik, bez akcji) służy do podglądu dowolnego pliku (historia, backupy rewersu). Standard animacji lightboxa: ≤ 120 ms (`ANIM_MS`).
- `mask_editor.py` — `MaskEditorDialog(suit, template_path, wartosc=None)`: rysowanie pędzlem/gumką strefy pop-out w AKTYWNYM presecie masek; `wartosc=None` = maska CAŁEGO KOLORU (przycisk w sekcji Tła przodu widoku Style → `back_view.edit_mask_clicked`), z wartością = maska JEDNEJ KARTY (przycisk „Edytuj maskę" na Ekranie roboczym → `edit_mask_requested(suit, wartość)`); wspólny handler `MainWindow._open_mask_editor(suit_nazwa, wartosc="")` (auto-tworzy preset przy aktywnej „automatycznej"). ### Osobliwości
- **AI nie rysuje tekstu.** Wartości/symbole narożne stempluje wyłącznie `compositor.stempluj_narozniki()` PO odpowiedzi API (oba tryby; FULL_AI dostaje dodatkowo `wyczysc_tarcze()`); prompty generujące kończą się `prompts.NO_TEXT_SUFFIX`. Nigdy nie wracaj do rysowania narożników przez model.
- `app/api/stability_client.py` to martwy kod dla generacji, ale jego `abort_active()`/`reset_abort()` są **żywym mechanizmem anulowania** używanym przez workery — nie usuwaj.
- `SegmentedControl` (`app/gui/widgets.py`): `set_current()` **nie emituje** sygnału `changed` — po programowej zmianie wołaj handler ręcznie.
- Suwaki: ZAWSZE `widgets.SnapSlider` (klik w tor = skok do pozycji, pageStep ~10%, kursor, kółko myszy IGNOROWANE), nigdy surowy `QSlider` — stylizacja w sekcji `QSlider` w `theme.QSS` (tor + gradientowe wypełnienie + duży uchwyt).
- Comba i spiny: ZAWSZE `widgets.NoScrollComboBox`/`NoScrollSpinBox`, nigdy surowe `QComboBox`/`QSpinBox` — kółko myszy jest ignorowane (`event.ignore()` → przewija stronę zamiast zmieniać wartość; przewijanie nad kontrolką w QScrollArea zmieniało preset/kolor przypadkiem). QSS w `theme.py` łapie podklasy — bez zmian.
- **`config.find_serif_font()` skanuje `assets/fonts/*.ttf` PŁASKO** (fonty repo leżą w podfolderach `ui/` i `karty/`, więc żaden się nie łapie) i spada na `C:\Windows\Fonts\georgia*/times*` → poza Windows rzuca `FileNotFoundError`, dopóki użytkownik nie wrzuci `.ttf` wprost do `assets/fonts/` albo nie ustawi czcionki w presecie `wartosci`.
- Fonty w `assets/fonts/ui/` służą wyłącznie interfejsowi; do rysowania kart używa się czcionek z `config.find_serif_font()` albo z biblioteki `assets/fonts/karty/` (`config.CARD_FONTS_DIR`, podfoldery = grupy, licencje w `LICENSES.md`) — combo w Style → Wartości narożne kopiuje wybrany plik do folderu aktywnego presetu (`style_store.save_font_file`), preset zostaje samowystarczalny.
- Stan użytkownika (gitignored): `projekt.json` (talia, przypisania, aktywne presety per kategoria, model, ustawienia pudełka i synchronizacji), `.env` (klucze), `Style/`, `output/`, `zdjecia/`, `.sync/`, `kopie_zapasowe/`.
- **PyQt nie hot-reloaduje kodu.** Po zmianie w `app/` trzeba ZRESTARTOWAĆ aplikację — inaczej testuje się poprzednią wersję i „poprawka nie działa".
- Ciężkie generacje (pudełko, komplet teł) robią wiele wywołań API pod rząd — nowe wtórne wywołania opakowuj w `_box_ai_opcjonalne` / retry z backoffem zamiast pozwalać, by jeden błąd sieci zabił całą sekwencję.
